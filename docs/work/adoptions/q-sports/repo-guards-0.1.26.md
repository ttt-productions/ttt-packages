# Adopt @ttt-productions/repo-guards 0.1.26

**What:** A new generic guard, `typedMocks`: every module mock names its module through `import('…')` and is typed against it through a shared fake or a typed helper, and no test overrides an export the app lists as one whose real behavior every test needs; `entryPurity` holds every runtime-specific entry to its runtime.
**Severity:** medium
**Came from:** the ttt-packages shared-standards Phase 3 repair session (ttt-prod scope)

- **Package and version:** `@ttt-productions/repo-guards` 0.1.26.
- **Release:** `./scripts/release-multiple.sh dev-standards firebase-helpers media-processing-core moderation-core monitoring-core notification-core query-core repo-guards ttt-core upload-core patch`.
- **What changed:**
  - `generic.typedMocks` is a required fact: `importAliases`, `fakes` (the same shared-fake list `sharedFakes` takes), `typedHelpers` (each an owner — a repo file, or a package entry such as `@ttt-productions/dev-standards/testing` — and the typed mock helpers it exports), and `forbiddenOverrides` (each a module, the exports no test overrides, and why). A package-entry owner must be an installed package whose manifest exports that entry.
  - "every module mock is typed against the module it replaces": a `vi.mock` / `vi.doMock` names its module through `import('…')` (a string path fails, even with a typed factory), and every return path of its factory goes through a listed shared fake or typed helper. A typed helper call writes no type argument and gets the factory's own `importOriginal` as its first argument. A mock with no factory, or with the runner's `{ spy: true }` options in its place, passes.
  - "no test overrides an export whose real behavior every test needs": a listed export is read only at the top level of each override object, so a nested property of that name passes; a spread of anything but the real module (`importOriginal()` / `vi.importActual`), a computed name, or an override object the guard cannot see fails.
  - The reader records `vi.mock(import('x'), …)` as one mock site of `x` (never as a dynamic import), so every guard that reads mocks — `sharedFakes`, the import-path guards — sees the new form.
  - `entryPurity` takes a new required fact, `testRunnerSegment` (`'testing'`): an entry whose last subpath segment it names (`./<runtime>/testing`) runs only inside the test runner, so "every universal and Node entry loads under plain Node" never loads it. Its purity check, renamed "every entry reaches only the runtimes its own runtime allows", now holds every runtime-specific entry (test-runner entries and reviewed exceptions included) to its runtime: a Node entry reaches no React or browser runtime, a browser entry no Node or React, a React entry no Node.
- **What the app must change:**
  - If the guard config declares `entryPurity` facts rather than `{ absent }`, add `testRunnerSegment: 'testing'`, and fix any runtime-specific entry the renamed check reports.
  - Declare `generic.typedMocks` in the guard config (the suite fails the config until it is there), listing `{ owner: '@ttt-productions/dev-standards/testing', names: ['passThroughModule', 'stubModule'] }` among `typedHelpers` (dev-standards 0.0.10 ships them) and the app's shared fakes among `fakes`; list any export the app wants the real one of in every test under `forbiddenOverrides`, or declare it `[]`.
  - Move every module mock to the `import('…')` form, returning through a shared fake or `passThroughModule(importOriginal, overrides)` / `stubModule(importOriginal, stubs)` from `@ttt-productions/dev-standards/testing`, with no type argument; any local copy of such a helper is deleted. A factory that called `importOriginal<T>()` with a type drops it (the `import('…')` form types `importOriginal` already).
- **Done when:** The guard config declares `typedMocks` with the dev-standards helpers, no local typed-mock helper copy remains, the lockfiles name `@ttt-productions/repo-guards` 0.1.26 or later, and both `typedMocks` guards and `entryPurity` are green.
