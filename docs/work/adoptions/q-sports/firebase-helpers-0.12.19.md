# Adopt @ttt-productions/firebase-helpers 0.12.19

**What:** Two Firebase test kits ship: an in-memory Admin Firestore with its FieldValue fake and a no-network Admin test app, and an in-memory client Firestore that answers reads with real SDK snapshots, both on one Firestore value model.
**Severity:** low
**Came from:** the ttt-packages shared-standards Phase 3 repair session (ttt-prod scope)

- **Package and version:** `@ttt-productions/firebase-helpers` 0.12.19.
- **Release:** `./scripts/release-multiple.sh dev-standards firebase-helpers media-processing-core moderation-core monitoring-core notification-core query-core repo-guards ttt-core upload-core patch`.
- **What changed:**
  - New entry `./server/testing`: `makeInMemoryFirestore()` (a real Admin `Firestore` over an in-memory store — every field filter operator, `orderBy` either way, `startAfter`, `limit`, `select()`, `count()`, `aggregate()`, collection groups, batches, and transactions with read-before-write and contention retry; values compared as Firestore compares them, an inequality field then the document name ordering the result, ties broken in the last order's direction; `serverTimestamp()` stored as the commit's `Timestamp`; per-document update times and a stale `delete({ lastUpdateTime })` refused; hooks to fail or hold reads, queries, and commits and a query log; `startAt`, `endAt`, `endBefore`, `limitToLast`, `offset` and a composite `Filter` throw), `FieldValueSentinel` / `fieldValueSentinels`, and `testAdminApp({ storageBucket? })` (Auth and Storage on a closed local port with no credential and Storage's retries off, so an unspied call is refused at once; a second call with other options throws).
  - New entry `./firestore-client/testing`: `makeInMemoryClientFirestore()`, whose `reads` are typed as `firebase/firestore`'s `getDoc`, `getDocFromServer`, `getDocs`, `getDocsFromServer`, `getCountFromServer`, `onSnapshot`; it evaluates the real query (composite filters and cursors included) and answers real SDK snapshots. A live listener answers after the call returns and again, on a later turn, after each change, and each later query answer's `docChanges()` holds its changes since the one before. Hooks fail a read, break a live listener (`failListeners`, its error delivered on a later turn), answer listeners from cache (`answerFromCache` / `answerFromServer`), hold an answer, and build the SDK's own `FirestoreError` (`firestoreError`).
  - `vitest` is a new optional peer. Nothing existing changed.
- **What the app must change:** Install only. Adopting the kits is optional: a test tree that keeps its own in-memory Firestore or hand-built client read doubles can move onto them. A test on the client kit waits for a listener's answer (`waitFor`, or an `await act(async () => …)` around the change), since none arrives inside the write that caused it.
- **Done when:** The lockfiles name `@ttt-productions/firebase-helpers` 0.12.19 or later, and the gate is green.
